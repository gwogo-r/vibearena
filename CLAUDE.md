# VibeArena

VibeArena — веб-MVP, который помогает маркетологу выбрать модель генерации изображений. Один промпт отправляется в две совместимые модели через VibeMarketolog Agent API, результаты показываются анонимно («Вариант A» / «Вариант B»), пользователь голосует вслепую и только потом видит названия моделей, цену и время генерации. Базовый режим — text-to-image; опционально можно загрузить фото товара, тогда сравниваются image-editing модели (товар сохраняется как есть, меняется только сцена).

Референсы механики: [Artificial Analysis Image Arena](https://artificialanalysis.ai/embed/text-to-image-leaderboard/arena), [LMArena — image generation](https://help.arena.ai/articles/1626988163-lmarena-how-to-use-image-generation).

API-документация: https://lk.vibemarketolog.ru/docs/agent-api

## Технологический стек

- Next.js (App Router) + TypeScript
- Tailwind CSS
- Next.js API routes (сервер) — весь доступ к VibeMarketolog API только отсюда
- Zod — валидация входа/выхода
- Локальное хранение голосов (без БД на MVP)
- Vitest — тесты ключевой бизнес-логики

## Принцип: максимально просто

Это MVP, не production-платформа. Не плодить слои абстракции, не делать "на вырост". Один аккуратный экран, минимум файлов, прямой код без лишних паттернов. Если можно решить одной функцией без интерфейса/фабрики — так и делать.

## Структура проекта

- `src/app/` — страницы и API routes (Next.js App Router)
- `src/lib/vibeApi.ts` — типизированный клиент VibeMarketolog: `getCapabilities()`, `estimateGeneration()`, `startGeneration()`, `getGenerationStatus()`
- `src/lib/` — остальная бизнес-логика (подбор совместимых параметров, работа с голосами) — простыми функциями, без лишних слоёв
- `src/components/` — UI-компоненты

## Команды

- `npm run dev` — запуск разработки
- `npm run build` — production build
- `npm run lint` — линт
- `npm run test` — тесты (Vitest, после установки)

## Правила и договорённости

- `VIBE_API_TOKEN` — только в переменной окружения на сервере. Никогда не передавать в браузер, не логировать, не коммитить. Обязателен `.env.example` (без значения токена).
- Каталог моделей загружается динамически через `GET /api/agent/capabilities` — не хардкодить список моделей.
- Платную генерацию (`POST /generate`) нельзя вызывать без явного подтверждения пользователем после показа сметы.
- Для каждой из двух параллельных генераций — свой UUID `idempotency_key`. При сетевом повторе того же запроса — не создавать новый ключ.
- Если обе модели поддерживают одинаковый `aspect_ratio` — использовать одно значение для обеих. Seed — одинаковый только если обе модели его поддерживают; иначе не передавать seed никому и явно предупредить о факторе случайности.
- До голосования запрещено показывать: название модели, провайдера, цену конкретного результата, `generation_id`. Обе карточки во время голосования — одинаковое оформление и размер.
- Demo mode (когда `VIBE_API_TOKEN` отсутствует): честная имитация полного сценария на fixture-данных, с явной меткой «Demo mode — генерация не выполнялась». Не имитировать реальные вызовы скрытно.
- Ошибки — понятным текстом на русском; при наличии `request_id` — показывать его пользователю.
- Не позволять пользователю подставлять произвольный API URL.
- Новый функционал должен быть покрыт тестами: юнит-тесты обязательны (особенно подбор совместимых параметров и обработка статусов генерации), интеграционные — если для стека есть подходящая инфраструктура.
- Фото товара (опционально): без фото — список моделей ограничен теми, кому фото не обязательно (обычный text-to-image); с фото — только модели с поддержкой `image_input`, промпт автоматически дополняется инструкцией сохранить товар как есть.

Полный сценарий, ограничения MVP, структура записи голоса, требования к README и критерии готовности — см. [[project-context]] в памяти проекта (сохранён полностью из исходного ТЗ).
