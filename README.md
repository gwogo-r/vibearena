# VibeArena

Слепое A/B-сравнение моделей генерации изображений через [VibeMarketolog Agent API](https://lk.vibemarketolog.ru/docs/agent-api) — чтобы маркетолог мог выбрать модель по факту результата, а не по техническим характеристикам в каталоге.

## 1. Проблема

В Agent API доступно множество моделей генерации изображений от разных провайдеров. Обычному маркетологу сложно понять, какую модель использовать для баннера, карточки товара, фотореализма или изображения с русским текстом. Каталог моделей показывает технические параметры, но не отвечает на вопрос «что лучше для моей задачи?».

## 2. Предложенное решение

Один и тот же промпт отправляется в две совместимые модели. Результаты показываются анонимно как «Вариант A» и «Вариант B». Пользователь выбирает лучший результат — и только после голосования видит названия моделей, стоимость и время генерации.

## 3. Почему слепое сравнение

Когда пользователь заранее знает название модели, бренд и репутация провайдера влияют на оценку сильнее, чем реальное качество результата. Слепое голосование убирает этот эффект: решение принимается по картинке, а не по имени модели. Раскрытие цены и времени после голосования добавляет к вкусовой оценке практический критерий «стоит ли это своих денег и времени».

## 5. Архитектура

Next.js App Router, один экран с последовательными состояниями. Все обращения к VibeMarketolog идут только через собственные API routes — токен никогда не попадает в браузер.

```
src/app/
  page.tsx                              — точка входа, рендерит ExperimentFlow
  api/agent/capabilities/route.ts       — прокси к GET /capabilities (+ demo mode)
  api/agent/generate/estimate/route.ts  — прокси к POST /generate/estimate
  api/agent/generate/route.ts           — прокси к POST /generate
  api/agent/generation/[id]/status/route.ts — прокси к GET /generation/{id}/status
  api/agent/upload-media/route.ts       — прокси к POST /upload-media (загрузка фото товара)

src/lib/
  vibeApi.ts     — типизированный серверный клиент VibeMarketolog
  demo.ts        — fixture-каталог и симуляция для demo mode
  compat.ts      — подбор совместимых параметров (aspect_ratio, seed) и фильтр моделей по режиму фото
  schemas.ts     — Zod-валидация входящих запросов
  errors.ts      — русские сообщения об ошибках API
  votes.ts       — локальное хранение и агрегация голосов (localStorage)
  experiment.ts  — тип состояния варианта A/B
  types.ts       — общие типы

src/components/
  ExperimentFlow.tsx  — оркестрация состояний эксперимента
  SetupStep.tsx        — настройка: категория, промпт, фото товара, модели, формат
  ModelCatalogTable.tsx — таблица цен/параметров всех моделей текущего режима
  EstimateStep.tsx      — предварительная смета и подтверждение
  GeneratingStep.tsx    — независимый прогресс двух вариантов
  CompareStep.tsx       — слепое сравнение + голосование
  RevealStep.tsx         — раскрытие моделей, цены, времени
  ResultsSummary.tsx     — агрегированная статистика экспериментов
```

Состояние эксперимента живёт в одном React-компоненте (`ExperimentFlow`) через `useState` — без Redux/Zustand и без БД. Голоса хранятся в `localStorage` браузера.

## 6. Использованные методы VibeMarketolog API

- `GET /capabilities` — динамический каталог image-моделей и их параметров
- `POST /upload-media` — загрузка фото товара, получение стабильной ссылки (только в режиме сравнения с фото)
- `POST /generate/estimate` — предварительная бесплатная смета (`strict: true`)
- `POST /generate` — запуск генерации с `idempotency_key` (свой UUID на каждый вариант)
- `GET /generation/{id}/status` — поллинг статуса каждые ~12 секунд

### Режим с фото товара (image-editing)

Загрузка фото товара — необязательный шаг. Если фото не загружено, работает обычный text-to-image
(как в исходном сценарии). Если фото загружено:

- список моделей для A/B сужается до тех, что умеют принимать `image_input` (по данным `/capabilities`);
- в `estimate`/`generate` обеим моделям передаётся `image_input: [url]` с одной и той же ссылкой;
- промпт автоматически дополняется инструкцией сохранить товар как есть: *«Keep this exact product
  pixel-identical, do not redesign it.»* — модель должна только поместить товар в новую сцену;
- все остальные правила (смета до генерации, слепое сравнение, голосование, раскрытие после голоса,
  idempotency_key, demo mode) не меняются.

Базовый URL и токен зашиты только на сервере (`src/lib/vibeApi.ts`) — клиент не может подменить API URL.

## 7. Инструкция запуска

```bash
npm install
npm run dev
```

Открыть http://localhost:3000

## 8. Настройка VIBE_API_TOKEN

Скопировать `.env.example` в `.env.local`:

```bash
cp .env.example .env.local
```

и указать токен из личного кабинета VibeMarketolog (`https://lk.vibemarketolog.ru/#agent` → «API-ключи»):

```
VIBE_API_TOKEN=ваш_токен
```

Без токена приложение работает в demo mode.

## 9. Demo mode

Если `VIBE_API_TOKEN` не задан, приложение честно имитирует полный сценарий:

- fixture-каталог из 5 demo-моделей с разными наборами параметров (в т.ч. одна — только image-editing);
- фиктивная смета с ценами и остатком баланса;
- симулированная генерация (~6 секунд) с двумя локальными demo-изображениями (`public/demo/*.svg`);
- загрузка фото в demo mode превращает файл в `data:`-URL на сервере (честно показывает именно то фото, что выбрал пользователь, без реального хранилища);
- явная плашка «Demo mode — генерация не выполнялась» на каждом экране.

Ни один реальный вызов к VibeMarketolog не выполняется — demo-логика полностью изолирована в `src/lib/demo.ts`.

## 10. Ограничения MVP

Реализован text-to-image и (опционально, с загруженным фото товара) базовый image-editing одним референсным
фото. Не реализовано: видео, авторизация пользователей, оплата, команды/рабочие пространства, полноценная
рейтинговая система, автоматическая оценка изображений, запуск рекламных кампаний. Хранение голосов — только
в браузере (localStorage), без сервера/БД. Автовыбор пары моделей учитывает только цену — параметр «качество»
(basic/high) в реальном каталоге поддерживает лишь 1 модель из 21, поэтому это не самостоятельный критерий
ранжирования, только видимая колонка в таблице.

## 11. Идеи развития
